সঞ্চয়-স্পেকের সব ৬৭টি পেজই তৈরি — MVP ৪১ + Phase 2-এর ১৯ + Phase 3-এর ৭ = Member ২১ · Admin ৩৮ · Shared ৮। Phase 1A-তে ছিল টাকার মূল চক্র (২০); 1B-তে স্কিম, নিবন্ধন, বকেয়া, স্টেটমেন্ট (১১); তারপর সিদ্ধান্ত-গ্রহণের পেজ (A-05, A-09, A-11, A-15, A-23) ও ৫টি অবকাঠামো পেজ। Phase 2 যোগ করেছে মাঠ সংগ্রহক মোবাইল ড্যাশবোর্ড (A-02), অবস্থা পরিবর্তন ও মৃত্যু দাবি (A-12, A-14), বাল্ক এন্ট্রি ও CSV ইমপোর্ট (A-18, A-19), হিসাব নিয়ন্ত্রণের পুরো স্তর (A-26 ফরেনসিক বিবরণ, A-27 রিভার্সাল, A-28 দিনশেষ ক্যাশ বুক, A-29 তহবিল স্থানান্তর, A-30 রিকনসিলিয়েশন), পরিচালনা (A-32 রুট পরিকল্পনা, A-33 রিমাইন্ডার, A-34 রিপোর্ট কেন্দ্র), সদস্যের বন্ধ-প্রিভিউ/নোটিশ/নমিনি/সেটিংস (M-15, M-17, M-19, M-20) এবং প্ল্যাটফর্ম সেটিংস ও অফলাইন sync (S-03, S-08)। Phase 3 (এবার) যোগ করেছে গভর্ন্যান্স স্তর — সদস্য স্থানান্তর (A-16), আর্থিক বিবরণ ও রেগুলেটরি রিটার্ন (A-35), সেটিংস হাব (A-36), স্টাফ/রোল/পারমিশন ও CRUDA ম্যাট্রিক্স (A-37), অপরিবর্তনীয় অডিট লগ (A-38), সদস্যের সহায়তা ও অভিযোগ কেন্দ্র (M-21) এবং নোটিফিকেশন পছন্দ (S-04)। প্রতিটি স্ক্রিনের নিচে তার উদ্দেশ্য, ভূমিকা, অবস্থা ও স্পেক রেফারেন্স লেখা আছে। ৬৭-পেজ তালিকার কোনো পেজই বাকি নেই। এর উপর এখন Admin App (Mobile-first) স্তর যোগ হচ্ছে: Somobay একটি মোবাইল অ্যাপ, তাই Admin Panel-ও মোবাইলে পুরোপুরি ব্যবহারযোগ্য হবে, সাথে Desktop Web-এ বড় স্ক্রিনের আলাদা Dashboard Layout। দুটি আলাদা Business Logic বা Database নয় — একই Backend, একই API, একই নিয়ম (BR-01…BR-15, D-22); শুধু UI আলাদা। নেভিগেশন রোলভিত্তিক শেলে (D-35): মাঠ · হিসাব · অনুমোদন · প্রশাসন · পর্যবেক্ষণ। Leg A-তে শেল + ৬টি মোবাইল প্যাটার্ন + AM-01/02/03; Leg B-তে AM-04…AM-11 (সদস্য খোঁজা, ৩৬০°, জমা এন্ট্রি, নিবন্ধন, আবেদন যাচাই, সম্পাদনা, অ্যাকাউন্ট বিবরণ, প্রস্থান নিষ্পত্তি)। Leg C-তে AM-12…AM-19 (বকেয়া রেজিস্টার, ফরেনসিক অডিট ট্রেইল, সংশোধন/রিভার্সাল, দিনশেষ ক্যাশ বুক, নিষ্পত্তি ও পেমেন্ট, সাধারণ লেজার, অবস্থা পরিবর্তন, মৃত্যু দাবি)। Leg D-তে AM-20…AM-26 (তহবিল স্থানান্তর, রিকনসিলিয়েশন, বাল্ক জমা, CSV ইমপোর্ট, আর্থিক বিবরণ ও রিটার্ন, রিপোর্ট কেন্দ্র, স্কিম বিবরণ)। Leg E-তে AM-27…AM-35। এরপর বহু-মডিউল আর্কিটেকচার (specs/03) অনুযায়ী ROSCA মডিউল (Phase 1B) যোগ হয়েছে: Admin RA-01…RA-12 (প্রতিটির ডেস্কটপ + মোবাইল অ্যাপ রূপ = ২৪ স্ক্রিন) ও সদস্যের RM-01…RM-06 (৬ স্ক্রিন) = ১৮ লজিক্যাল পেজ · ৩০ স্ক্রিন। এরপর Joint Goal মডিউল (Phase 2A) যোগ হয়েছে: Admin JA-01…JA-10 (ডেস্কটপ + মোবাইল = ২০ স্ক্রিন) ও সদস্যের JM-01…JM-05 = ১৫ লজিক্যাল পেজ · ২৫ স্ক্রিন। সবশেষে কর্জে হাসানা মডিউল (Phase 3A): Admin QA-01…QA-17 (ডেস্কটপ + মোবাইল = ৩৪ স্ক্রিন) ও সদস্যের QM-01…QM-08 = ২৫ লজিক্যাল পেজ · ৪২ স্ক্রিন; সর্বমোট ১২৫ পেজ · ১৯৯ স্ক্রিন। ROSCA-র ফ্লো F-09…F-12, Joint Goal-এর F-13/F-14 ও কর্জে হাসানার F-15…F-17 এখনো তৈরি নয়। সব অঙ্ক ডিফল্ট সিদ্ধান্ত (specs/02-open-decisions.md) অনুযায়ী হিসাব করা — হার্ডকোড নয়: উত্তোলনযোগ্য ব্যালেন্স প্রতিটি স্ক্রিনে posted − hold − সর্বনিম্ন − লক-ইন সূত্রে গণনা হয়েছে। কোনো সুদ/মুনাফার হিসাব কোথাও নেই।

C · ADMIN APP (MOBILE-FIRST LAYER)

অ্যাডমিন মোবাইল অ্যাপ — একই Backend, একই নিয়ম, আলাদা UI (Leg A + B + C + D + E = ৩৫ স্ক্রিন)

Somobay একটি Mobile-first অ্যাপ: Admin Panel মোবাইলে পুরোপুরি ব্যবহারযোগ্য, সাথে Desktop Web-এ বড় স্ক্রিনের আলাদা Dashboard Layout। দুটি আলাদা Business Logic বা Database নয় — একই API, একই ব্যাবসায়িক নিয়ম (BR-01…BR-15), একই অনুমোদন সীমা (D-22)। নিচের স্ক্রিনগুলো সেই একই ডেটা ও ইঞ্জিন ব্যবহার করে, শুধু ৩৯০px-এর জন্য আলাদা লেআউট। নেভিগেশন রোলভিত্তিক শেল (D-35): মাঠ (COLLECTOR) · হিসাব (ACCOUNTANT) · অনুমোদন (MANAGER/APPROVER) · প্রশাসন (ORG_ADMIN) · পর্যবেক্ষণ (AUDITOR/VIEWER)। বটম নেভ ঠিক ৫ স্লট (৪টি কাজ + কেন্দ্রীয় FAB, অথবা FAB ছাড়া ৫টি কাজ), বাকি সব হ্যামবার্গার ড্রয়ারে — ড্রয়ারে সর্বদা সম্পূর্ণ ANAV (২৫ আইটেম / ৬ গ্রুপ)।
